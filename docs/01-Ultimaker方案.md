# 01 · Ultimaker / Marlin 方案

> 共用部分见 [00-共用内核](00-共用内核.md)。本文只写这条路**独有**的东西：硬件改造、方言实现、时序风险、限制。

---

## 0. 先说清楚：这条路的前提

「基于 Ultimaker」有三种完全不同的含义，选错会白干：

| 含义 | 说明 | 可行性 |
|---|---|---|
| **A. 保留 Ultimaker 原厂主板 + Marlin** | 刷/改 Marlin，用 `M42` 驱阀 | 取决于机型，见下表 |
| **B. 借 Ultimaker 的机械结构，换主板** | 结构是 Ultimaker，控制是自己的板或 Klipper | ✅ 最好走（DIW-UM 那台就是这类） |
| **C. 买 Ultimaker 整机改造** | 保留一切，只换打印头 | ⚠️ 新款锁死 |

**本文按 A 写**（Marlin 路线），因为 B 的「换主板」实际会落到 [02-Klipper](02-Klipper方案.md) 或自研板，C 基本不可行。

### 机型决定了能不能做

| 机型 | 主板 | 固件 | 可改性 | 结论 |
|---|---|---|---|---|
| **Ultimaker Original / Original+** | Arduino Mega 2560 + Ultimaker Shield | Marlin（开源） | ⭐⭐⭐⭐⭐ 源码公开，avrdude 直接刷 | **首选** |
| **Ultimaker 2 / 2+ / Extended** | UM2 board（ATmega2560） | Marlin 派生，Ultimaker 自己维护 | ⭐⭐⭐ 社区有 Tinker 固件，可刷 | **可行**，但要自己合代码 |
| **Ultimaker 3 / S3 / S5** | ARM，闭源 | Marlin 派生但锁死 | ⭐ 无源码、有签名/加密、NFC 耗材识别 | **放弃** |

> ⚠️ **这一条必须先确认。** 如果是 3/S3/S5，Marlin 路线不成立，直接转 02 或自研板。

## 1. 硬件改造（DIW 化）

Ultimaker 是 **XY 走打印头、Z 走热床** 的结构（Original 和 2 都是）。这对 DIW 有两个影响：

**好处**：Z 轴负载是床+工件，喷头不用抬整个平台，抬针动作轻。

**坏处**：XY 龙门是**为 Bowden 设计的轻量化结构**，加装注射器会显著增加运动质量。Ultimaker 的 XY 加速度标称 3000–5000mm/s²，但那是空载。

### 必须做的五件事

1. **拆掉原挤出机（feeder）和热端**
   Bowden 管、送丝齿轮、加热块、喷嘴全部拆除。注意 Ultimaker 2 的 feeder 在机身背面，拆掉后机身重心会变。

2. **装注射器支架 + 阀**
   30CC 料筒最合适（重量 < 200g 含料）。**阀要尽量靠近喷嘴**——阀到针尖的管路容积就是「关阀后还会挤出来的量」，越短越好。
   参考 [Jubilee 10cc 注射器工具](https://github.com/machineagency/jubilee_syringe_tool) 的结构（CC-BY），但那个是步进推杆，你是气动，只需要支架。

3. **气路**：调压阀 → 电磁阀 → 料筒。**加一路排气阀**（见 00 文档 §5 和 PRIOR_ART），防拉丝靠泄压不靠等。

4. **找一路空闲输出引脚**
   - Ultimaker Original：Shield 上有未用的 AUX 口，`M42 P<pin>` 用 Arduino 引脚号
   - Ultimaker 2：主板上有扩展口，但需要查原理图确认哪根是空闲 GPIO
   - **驱动能力**：`M42` 输出的是 MCU 的 3.3V/5V 逻辑，**电流只有几十 mA，绝不能直接驱动电磁阀**。必须经 MOS 管或继电器板，并加续流二极管。

5. **禁用温度保护**
   - Marlin 编译选项：`TEMP_SENSOR_0 998`（假传感器，恒温 25℃）
   - 或运行时 `M302 S0`（允许冷挤出）
   - `HEATER_0_MAXTEMP` 保留默认即可，反正不加热

> ⚠️ Ultimaker 2 有耗材检测/材料识别。如果保留原主板，需要确认拆掉 feeder 后不会报错停机（部分固件会检测 feeder 编码器）。

## 2. 方言实现

```ts
const MarlinDialect: Dialect = {
  name: 'marlin',

  caps: {
    queuedIO: false,        // ⚠️ 关键：M42 由解析器执行，不随运动排队
    arcs: true,             // Marlin 支持 G2/G3，但我们的板不支持，统一不用
    multiCmdPerLine: false,
    maxLineLen: 96,         // Marlin 默认 MAX_CMD_SIZE
    dwellUnit: 'ms',
  },
  ...
}
```

### 指令映射

| 抽象 | Marlin 指令 | 备注 |
|---|---|---|
| 开/关阀 | `M42 P<pin> S<0\|1>` | 原始引脚写。**解析器执行** |
| 开/关阀（备选） | `M280 P<idx> S<pos>` | 舵机式，适合夹管阀 |
| 驻留 | `G4 P<ms>` | 毫秒 |
| 等运动停止 | `M400` | **本方案的关键补救指令** |
| 空驶 | `G0 X.. Y.. F..` | |
| 打印段 | `G1 X.. Y.. F..` | |
| 抬针 | `G1 Z.. F..` 或 `G0 Z..` | Z 是热床，正方向 = 床下降 = 远离喷头 |
| 回零 | `G28` | |

### 生成的 G-code

```
; ── stroke s1 (contour) ──────────
M400                       ; ① 等前面所有运动结束
M42 P11 S0                 ; ② 确保阀关（幂等）
G0 X10.000 Y10.000 F6000   ; ③ 空驶到起点
G0 Z0.400 F3000            ; ④ 降到位
M400                       ; ⑤ 等定位完成 ← 必须
M42 P11 S1                 ; ⑥ 开阀
G4 P120                    ; ⑦ 上升延时
G1 X50.000 Y10.000 F600    ; ⑧ 打印
G1 X50.000 Y40.000 F600
G1 X10.000 Y40.000 F600
G1 X10.000 Y10.000 F600
G1 X10.000 Y13.000 F600    ; ⑨ 终点前 Δ 处切一刀（Δ = 600mm/min × 80ms = 0.8mm）
M400                       ; ⑩ 等这一段走完
M42 P11 S0                 ; ⑪ 关阀
G4 P80                     ; ⑫ 拖尾
G0 Z0.700 F3000            ; ⑬ 抬针
```

### ⚠️ 为什么到处是 `M400`

因为 **`M42` 是命令解析器执行的，不进运动规划队列**。这是 Marlin 的已知缺陷，见 [issue #26803](https://github.com/MarlinFirmware/Marlin/issues/26803)（closed as not planned）。

后果：一个长移动期间发出的 `M42`，要等移动**结束之后**才真正翻转引脚。报告者实测：50–100ms 驻留「有时候行有时候不行」，要 1000ms 才可靠。

**所以我们强制在每个 `M42` 前插 `M400`。** 代价是每条笔画两端各多一次完整停车-启动（约 0.2–0.4 秒）。对 DIW 可以接受——参考机本来就是逐笔画停车打出来的。

**如果 `caps.queuedIO=false`，后处理器必须自动插入这些 `M400`，不能依赖用户手写。**

## 3. 三个候选解法（按推荐度）

### 解法一：`M400` 兜底（本文默认）

**优点**：正确、简单、任何 Marlin 都能用。
**缺点**：每条笔画多两次停车；线宽在起停处会有轻微变化（速度从 0 加速）。

**缓解**：把 `minSegmentLen` 提到 2mm 以上（见 00 文档 §5 的加速距离表），并且驻留量按「停车后」标定。

### 解法二：借用激光功能的 S 值内联（需实测）

Marlin 有 `LASER_FEATURE` / `SPINDLE_LASER_PWM`，支持在 `G1` 里带 `S<功率>`：

```
G1 X50 Y10 S1000
G1 X50 Y40 S0
```

如果这个 `S` 是由**规划器**处理（随运动同步），那就绕过了 `M42` 的时序问题，而且不用停车。

**⚠️ 未经验证。** 需要查 Marlin 源码确认 `S` 是否走 planner，或在真机上用示波器测。如果成立，这是这条路最优解。

**风险**：需要改固件编译选项，且 `S` 的语义是 PWM 功率，映射成「开/关阀」需要 `S0`/`S255` 二值化。

### 解法三：换固件（等于放弃这条路）

把 Ultimaker 主板刷成 Klipper —— 但 Klipper 需要 Linux 主机 + 支持的 MCU，AVR 板子支持有限（Klipper 支持 AVR 但性能受限）。

**实际做法**：保留机械，换主板，走 [02-Klipper](02-Klipper方案.md)。

## 4. 时序可信度评估

| 项 | Marlin 表现 | 影响 |
|---|---|---|
| IO 是否随运动排队 | ❌ 否 | 必须 `M400` |
| 队列深度 | 16 条（`BLOCK_BUFFER_SIZE`） | 比自研板的 8 深，但 `M400` 会清空 |
| 无 look-ahead？ | ✅ 有前瞻规划 | **比自研板好**——短线段能保持速度 |
| 单条运动时长上限 | 无（除非自己加） | 比自研板的 60s 宽松 |
| 指令行长上限 | **96 字节**（默认） | 必须控制行长 |
| 通讯流控 | 串口 `ok` 握手 | 下发器要实现「发一行等一个 ok」 |

**注意最后两条**：Marlin 的串口协议是逐行 `ok` 确认的，跟自研板的 UDP 完全不同。下发器不能复用，要重写。

---

## 5. 限制清单

1. **`M42` 时序不可信** —— 最大的坑，已给解法。
2. **96 字节行限制** —— `G1 X10.000 Y10.000 F600` 是 25 字节，安全。但别加长注释。
3. **串口速度** —— Ultimaker 的 USB 串口 115200 或 250000。逐行 `ok` 握手，实际吞吐约 100–200 行/秒。一条笔画 10 行，即 10–20 笔画/秒，够用。
4. **`M400` 会清空前瞻** —— 每条笔画之间必然停顿，无法做连续路径。这是硬限制。
5. **Ultimaker 2 的耗材检测** —— 拆 feeder 后可能报错。
6. **不能改软限位** —— 除非改固件重编（`X_MAX_POS` 等）。
7. **无 `M114` 实时位置**（有，但精度到 0.001，够用）。

## 6. 与自研板（LCSystem）的差异对照

| 项 | LCSystem | Ultimaker/Marlin |
|---|---|---|
| 阀指令 | `M121 U<n> V0/1` | `M42 P<pin> S0/1` |
| IO 排队 | 待测 | ❌ 确定不排队 |
| 队列深度 | 8 | 16 |
| 行长度 | 128 B | 96 B |
| 通讯 | UDP，无重传 | 串口，`ok` 握手 |
| 无前瞻 | 可能 | ✅ 有前瞻 |
| 圆弧 | ❌ 无 | ✅ 有（但我们不用） |
| 软限位 | 可改宏 | 需重编 |

**共同点：都需要「终点前 Δ 处切一刀 → 停车 → 关阀 → 驻留 → 抬针」这个骨架。** 骨架相同，只是指令名不同。

## 7. 实施步骤

| 步 | 做什么 | 需要硬件 |
|---|---|---|
| 1 | 确认机型（Original / 2 / 3+） | 否 |
| 2 | 写 `MarlinDialect`（约 80 行） | 否 |
| 3 | 用 mock 板验证 G-code 结构 | 否 |
| 4 | 找空闲引脚、量电平、接 MOS 板 | 是 |
| 5 | **测 `M42` 时序**：塞满队列 → `M42` + `G4 P200` → 示波器/万用表看脉冲 | 是 |
| 6 | 测解法二（激光 S 内联）是否可行 | 是 |
| 7 | 标定（00 文档 §5 三组实验） | 是 |

**第 5 步是决策点**：如果 `M42` 真的解析器执行（大概率），就锁定解法一；如果意外地排队，那 Marlin 路线的可用性会大幅提升。

---

## 8. 什么时候该放弃这条路

出现以下任一情况，转 02 或自研板：

- 机型是 Ultimaker 3 / S3 / S5（无源码）
- 无法找到空闲 GPIO，或引脚已被占用无法释放
- 需要「连续路径不停车」（Marlin 的 `M400` 做不到）
- 需要精确的 sub-100ms 时序（`M42` 做不到）
- 需要改软限位/加速度超出固件范围

---

## 9. 一句话总结

**这条路能用，但它是「将就」**：靠 `M400` 强制停车换取时序正确，代价是速度慢、无法连续路径。适合**快速验证概念**（手里正好有台 Ultimaker），不适合**做产品**。

真正的产品形态应该是自研板或 Klipper——因为那两条路的 IO 可以随运动排队，不需要停车。
