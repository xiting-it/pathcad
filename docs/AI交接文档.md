## 1. 三十秒看懂

**这是什么**：CAM-B 是一个**路径工艺平台**上位机。用户画路径（手绘/SVG/3D模型切片），每条路径绑定一个「工具」，工具在路径两端控制输出通道 + 延时，编译成指令序列后下发到运动控制板。

**不是切片器**。切片器是「模型→层轮廓→填充」，这里核心是**路径本身就带工艺事件**。

**支持工艺**：气动挤出（DIW，已实现）、激光切割/打标（接口预留，P4 待定）。

**谁在用**：用户做上位机（**零基础，不懂 CAM 术语**），朋友提供硬件。用户是自己掏钱做产品，不是玩票。

**代码量**：Python 约 6000 行（15 模块）+ 前端约 6500 行（8 文件，**零框架零构建**）。

## 4. 绝对不能碰的红线

### 4.1 每条筋必须是独立笔画

```
❌ 蛇形连接：连接段会带着工具开着，在空白处漏料
✅ 每条筋各自开关工具
```

### 4.2 「抬针 → XY 空驶 → 落针」必须是三段独立动作

```
❌ G0 X0.4 Y0.6 Z0    ← 针头贴着工件表面斜着蹭过去，撞坏已打印的格栅
✅ 三段分开
```
曾经为了省指令数合并过（63→46 条），看到输出坐标序列后立刻回退。

### 4.3 安全高度绝不能取机器行程

```python
safe = max(travel_z, lift+1)      # ❌ 默认 travel_z=100 → G0 Z100
safe = 最高层z + 抬针 + 1mm        # ✅
```
**这条烧过电机**：机器 Z 实际只有几毫米时，`G0 Z100` 让它顶到机械上限**堵转**，满电流不转，几分钟烧绕组绝漆。

### 4.4 中止 ≠ 立刻停机器

板子**没有清空队列的指令**。中止后队列里最多还有 8 条会继续执行。
必须发 `M400` 等队列排空（已实现 `JobRunner.drain()`），**排空前禁止重发**，否则新旧命令混跑、动作错乱。

### 4.5 恒速挤出

开关式挤出的挤出量由阀的开关决定，**不由速度决定**。速度一变线宽就变。
所以速度是**全局工艺约束**，不能做成按路径可调。

## 5. 硬件真相（全部实测，文档有错的地方已标出）

### 5.1 只有一块板要认真对待

| 板子 | 定位 |
|---|---|
| **H5 / FSCSystem01** | **唯一主力**，四轴 + 4 路 IO |
| R7 网口板 | 测试消耗品，只保留能跑 |
| F1 串口板 | 玩具，只保留能跑 |

用户原话：「以后的板子只会比H5板子更完善，R7理论上只用来作为测试消耗品，串口F1的板子更是当玩具」

### 5.2 H5 的关键事实

- **连接**：UDP `192.168.0.102:5000`，电脑网卡配静态 `192.168.0.100/24`
- **多网卡机器必须 `bind(("192.168.0.100", 0))`**，否则可能走 WLAN 出去收不到回包
- **电机接口**（左侧一列，**从下往上编号**）：**CN6=X、CN7=Y、CN8=Z、CN9=U**
- **第四轴丝印写 `U`，但指令必须发 `E`**（实测 `G1 E0.01 F300` → E000）
- **回码**：G 行回 `E` 码、**纯 M 行回 `B` 码**
- 🔴 **`G4` 的 `P` 单位是秒，不是文档写的毫秒**：120ms 写 `G4 P0.12`。
  按文档写 `G4 P100` 会让板子睡 100 秒，看起来像"卡死"
- **IO 输出只有 4 路**（`U0~U3`），文档和板子规格一致
- **软限位**：X ±1000、**Y ±2000**（文档写 ±1000，错了）、Z ±500
- 校验和是**十进制 XOR**（如 `*110`），不是十六进制
- `M18/M84` 无效（ENN 硬件下拉常使能，上电四轴就锁死）
- 板子忙时不处理新指令，`M114`/`G1` 会无回包——**不是卡死，是在忙**

### 5.3 回原点（回源）

界面入口：**机器 → 回原点（回源）…**，调 `G28`，可单轴选。

⚠️ **这是危险操作**：原点开关没接时，电机会一直往负方向找原点直到固件 60 秒超时
（`E013`），这段时间满电流堵转**足以烧毁绕组**。

所以实现上有四道保护：
1. 只由用户手动点击触发，绝不自动执行
2. 对话框先读 `M120` 把四轴原点开关状态显示出来（到位/未到位）
3. 任务正在发送时拒绝回原点
4. 回原点前自动排空队列

**测试前请确认这台机器的原点开关确实接好了。** 板子目前不在线（`以太网 2` 网卡已移除），
所以这个功能只做过离线验证，**没在真机上跑过**。

### 5.4 板子的三条硬限制（制作组确认）

1. **不支持断点续传** —— 中止后只能从头重打
2. **不支持队列清空** —— 协议里没有任何清空指令
3. **只能断电清空队列**

→ 直接推出的产品需求：**长任务风险极高，应该支持分段打印**（还没做）。

### 5.5 会卡死板子的操作（只能断电）

- **R7 发 `G4`** → 队列卡死回 E020，不自恢复
- **F1 空载发 `G28`** → 走到保护上限，坐标变 -6000，之后全被 E05 拒绝

## 7. 已知的坑（会重复踩的）

### 7.1 开环系统会说谎

步进电机是开环的。**板子回 `E000` + 坐标变了 + 计时精确，完全不能证明电机真的转了。**
唯一传感器是人眼。

判断电机有没有通电：
- **通电保持**：明显更硬，像有弹簧顶着，几分钟后温热
- **没电流**：只有齿槽力（一格一格），温度不变

### 7.2 电机过热 ≠ 电机坏了

**先查它是不是被命令走到了物理不可达的位置**（堵转）。这个方向比"查接线"更常见，因为软件 bug 也会造成同样的物理现象。

### 7.3 多个故障叠加时，不要用一个测试解释所有现象

本项目一次性遇到三个互不相关的问题，我反复把它们当成同一个病因，推错了两次。
**每个测试先声明并验证前提**（板子通电了吗？通信通吗？），一个测试只能证明一件事。

### 7.4 结果包解析

结果包是 `<码>\rX:.. Y:.. Z:.. E:..\rok\r`，**坐标和结果码在同一个包里**，见到码就 return 会丢数据。

**位置行的字母和数字之间有冒号**（`X:0.000`），不能用空格切分，要用正则。

queued / echo / result 是**三个独立的包**，中间隔几十毫秒，要收满再解析。
**每条指令前要 drain 清残留**，否则读到上一条的 echo。

### 7.5 切片出来的轮廓必须简化

三角面切片会产生大量共线冗余点（一条直边被切成很多段），指令数翻倍。
`mesh.simplify_loop()` 已自动处理（`simplify_tol=0.02mm`）。**简化后要比对包围盒确认几何没变。**

### 7.6 前端容易踩的两个

- **改了代码行为没变**：先查服务是否重启 → 再查文件里函数有没有重复定义（`node --check` 查不出来，后定义的静默覆盖）→ 最后查浏览器缓存
- **移动 DOM 元素**：先 `grep` 出所有 JS 引用并加 null 保护；改完必须查 ID 唯一性

## 8. 下一步优先级

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 装好机械、逐轴点动确认方向 | 一切标定的前提，软件里可勾「轴方向反转」不用拆线 |
| **P0** | 测实际行程填进「机器设置」 | 防止再出现 `G0 Z100` 类事故 |
| **P1** | 打印第一个真实工件 | 从没打过，第一个件一定暴露新问题 |
| **P1** | 标定 `F` 值语义 | `G1 X20 Y20 F600` 实测比理论快 2.2 倍，若是最快轴速度则斜线线宽偏细，编译要按角度补偿 |
| **P2** | 标定开阀/关阀延时 | 20mm 直线，延时 0→300ms 每 50ms 一根 |
| **P2** | 轴验证面板（做成界面） | 现在只有命令行脚本 |
| **P3** | 分段打印 | 板子不支持续传，长任务一断就全白费 |
| **P3** | P4 激光接口 | 等合作方设备定 |
| **P4** | 脱机/SD 卡 | 要等固件加「读文件执行」+ 进度回读 + 出错行号上报 |
| **P4** | 启动优化（onefile→onedir） | 启动 5.57 秒，是唯一让用户觉得"不像成品"的地方 |

## 10. 和用户打交道的注意事项

用户**零基础，不懂 CAM/3D 打印术语**。已经形成的有效模式：

1. **先确认可行性再动手** —— 大工程开工前讲清「能做什么/不能做什么/依赖什么」，让他拍板
2. **不要一个个问，一次做完整可交付** —— 他的原话："我这样一个个问很难受的"。判断标准是**能不能立刻验证**，不是代码写完了
3. **架构级决策要问透** —— "一切拿不准的直接 grill me，不要心疼 token"
4. **判断界面的标准是"像不像工业软件"**，不是"能不能用"。不接受玩具感
5. **任何功能都要附带可操作说明**，不能只给界面
6. **他给资料时说"先不要改"** —— 那是要先读懂、复述理解、提疑问，等确认后再动手

**还有一条**：他问"现在可以投入使用了吗"这类问题，期待的是**分场景的诚实答案**（能用/不能用/需要什么前置条件），不是笼统的"可以了"。
