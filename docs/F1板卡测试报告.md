## 一、串口连接与收发

![串口通信完整记录](f1/01-serial-session.png)

完整的一问一答示例（CRC 旁路 `FFFF`）：

```
>>  @M50*FFFF\r
<<  D L000 R000 P 0.00 0.00 0.00*B545

>>  @G00 X0 Y0 Z0*FFFF\r
<<  E00*0907

>>  @G01 X20 Y15 F600*FFFF\r
<<  E00*0907

>>  @M50*FFFF\r
<<  D L000 R000 P 20.00 15.00 0.00*C7FB
```

**状态帧字段实测对照：**

| 字段 | 实际值 | 含义 |
|---|---|---|
| `L000` | 全 0 | 左限位 X/Y/Z 都未触发 |
| `R000` | 全 0 | 右限位 X/Y/Z 都未触发 |
| `P 20.00 15.00 0.00` | (20, 15, 0) | 当前坐标 mm，两位小数 |

坐标与刚才下发的 `G01 X20 Y15` 完全对应，说明**状态回读可信**。

## 二、速度与加速度

![速度测试](f1/02-speed-test.png)

**测试方法**：走固定 50mm，用不同 `F` 值，量实际耗时。

| F (mm/min) | 标称 (mm/s) | 实测耗时 | 实测 (mm/s) | 效率 |
|---|---|---|---|---|
| 60 | 1.00 | 50.00 s | 1.00 | **100.0%** |
| 120 | 2.00 | 24.99 s | 2.00 | **100.0%** |
| 300 | 5.00 | 10.00 s | 5.00 | **100.0%** |
| 600 | 10.00 | 5.00 s | 9.99 | 99.9% |
| 1200 | 20.00 | 2.50 s | 19.97 | 99.8% |
| 3000 | 50.00 | 1.00 s | 49.77 | 99.5% |
| 6000 | 100.00 | 0.51 s | 98.98 | 99.0% |

### 结论 1：无加减速

耗时**精确等于「距离 ÷ 速度」**，低速档（60/120/300）是 100.0%，说明是匀速启动、瞬间停止，完全没有加速段。

**对 DIW 打印反而是好事**：线宽取决于挤出量 ÷ 速度，速度恒定意味着**线宽恒定**。之前担心的「短线段跑不满速度导致线变粗」不会发生。

但有代价：瞬间起停意味着**换向时有冲击**，高速跑复杂路径可能丢步或抖动。目前空载看不出来，上真机后要注意。

### 结论 2：短线段没有额外开销

```
10 段 × 5mm  = 5.05 s
 1 段 × 50mm = 5.05 s
```

**完全相同**。因为无加减速，加上一问一答的应答延迟只有 3-5ms。

**这意味着可以自由切段**——不会因为段数多而变慢。填充算法可以放心地把长线切成短段，或者为了控制线宽而频繁变速。

## 三、圆弧（G02）

![圆弧 vs 直线对比](f1/03-arc-compare.png)

### 精度：完美

用 4 段 `G02` 画半径 10 的整圆，四个象限点：

| 象限点 | 实测坐标 | 实测半径 | 误差 |
|---|---|---|---|
| 1 | (0.00, 10.00) | 10.000 | 0.0000 mm |
| 2 | (-10.00, 0.00) | 10.000 | 0.0000 mm |
| 3 | (0.00, -10.00) | 10.000 | 0.0000 mm |
| 4 | (10.00, 0.00) | 10.000 | 0.0000 mm |

**零误差**，微线段逼近的精度完全够用。

### 但速度慢 2.7 倍

同样画半径 10 的整圆（周长 62.83mm）：

| F | 理论耗时 | G02 圆弧 | 32段直线 | 64段直线 |
|---|---|---|---|---|
| 300 | 12.57 s | **34.04 s (2.71×)** | 11.52 s (0.92×) | 11.72 s (0.93×) |
| 600 | 6.28 s | **17.09 s (2.72×)** | 5.86 s (0.93×) | 6.07 s (0.97×) |
| 1200 | 3.14 s | **8.61 s (2.74×)** | 3.04 s (0.97×) | 3.25 s (1.04×) |
| 3000 | 1.26 s | **3.52 s (2.80×)** | 1.34 s (1.07×) | 1.56 s (1.24×) |

比值**稳定在 2.7-2.8 倍**，各速度档都一样，说明是固件里的固定系数问题——很可能是微线段取得过短，或者每个微段都单独做了 1/2 步插值。

对比之下，直线离散的效率是 0.92-1.24 倍（接近理论值，略优于 100% 是因为实际弦长比圆周短）。

### 结论：不用 G02

- 慢 2.7 倍，打一个复杂零件会浪费大量时间
- 直线离散 32 段就够（半径 10 时弦高误差 0.048mm，远小于线宽 0.4mm）
- G-code 行数虽然多，但因为**无 short-segment 开销**，不影响速度

**如果以后要用圆弧**，需要朋友优化固件的微线段长度（现在是匀速微段，可以按弦高动态调整）。

## 五、CRC 校验

协议给了两种模式，都验证通过：

**① 旁路模式（推荐用于开发）**
```
@M50*FFFF\r      → 跳过校验，直接执行
```
所有测试默认用这个，省去反复算 CRC 的麻烦。

**② 真实 CRC**
```
@M50*5F53\r      → E00 / D 帧正常返回
@G00 X0 Y0 Z0*... → E00
@G01 X5 F600*...  → E00
```

两种模式都能通。**生产环境建议用真实 CRC**，能挡住线路干扰导致的错帧。

CRC 算法验证（对比文档示例）：
- `G01 X10.5 Y-3.2 F800` → 期望 `C692`，实算 `C692` ✅
- `E00` → 期望 `0907`，实算 `0907` ✅

## 六、运动期间的行为

```
发 G02 长圆弧（F60，约 8 秒）
0.5 秒后发 M50
← E07*79E0（系统忙）
```

**严格一问一答**：运动期间板子**既不回状态，也不接受新指令**。

这意味着：
- ✅ 上位机可以简单地「发一条等一条」，不用处理并发
- ❌ **打印过程中无法实时读取位置**——想知道进度只能在每条指令之间插 `M50`，但那会让耗时翻倍
- ❌ 无法中途暂停/恢复（协议里没有这个指令）

如果以后要做「打印进度显示」，只能在**笔画级别**估算：根据已发送的笔画数和总笔画数估算进度，而不是读真实坐标。

## 七、踩过的坑

### 坑 1：G28 空载会把坐标跑到 -6000

测试时发 `G28`（三轴回零），但**没接限位开关**，板子一直往负方向走，直到固件保护上限（`MOTOR_HOME_MAX_STEPS=300000`）才停：

```
第一次 G28 → 跑约 100 秒，返回 E09，坐标变成 -3000
第二次 G28 → 又跑一次，坐标变成 -6000
```

**后果**：坐标超过 ±2000，此后**所有移动指令都被 `E05` 拒绝**，板子变成"只会通信不会动"的状态。

**解法**：断电重启，坐标归零。

**教训**：
- 空载测试绝对不要发 `G28`
- 上真机前必须先接好限位开关

### 坑 2：协议文档比固件新

文档说 `G28 X` 可以按轴回零（v1.5 新增特性），但实测返回 `E04` 语法错误。

说明**板子固件版本比文档旧**。目前只能用不带轴的 `G28`（三轴同时回零）。

**要问朋友**：固件烧的是哪个版本？能不能更新到 v1.6？

## 八、对 CAM-B 的影响

### 已经确认的

| 结论 | 对软件的影响 |
|---|---|
| 串口不是网口 | `link.py` 要新增串口实现，前端连接面板要支持选 COM 口 |
| 无加减速 | 填充算法可以自由切段、自由变速，不用担心线宽变化 |
| 短线段无开销 | 笔画可以拆得很细，不用为了"减少段数"而合并 |
| 圆弧慢 2.7 倍 | 编译器继续用直线离散，不用 G02 |
| 运动中阻塞 | 进度显示只能按笔画估算，不能实时读坐标 |
| 指令集只有 5 个 | 没有 `G92` 清零、没有暂停、没有回抽 |

### 需要改的

1. **新增串口方言**（`dialects.py`）：帧格式 `@正文*CRC\r`，应答解析 `E<2位>*CRC\r`
2. **新增串口连接层**（`link.py`）：`LCSerialLink`，用 pyserial
3. **前端连接面板**：IP/端口 → COM 口下拉框 + 波特率
4. **打包**：exe 要带 pyserial

`app/dialects.py` 里新增 `F1Dialect`，只输出 F1 板支持的指令：

| 抽象操作 | F1 输出 | 说明 |
|---|---|---|
| 空驶 | `G00 X.. Y..` | 板子固定 3000mm/min，带 F 无效 |
| 打印段 | `G01 X.. Y.. F..` | |
| 抬针 | `G00 Z..` | |
| 开/关阀 | **（丢弃）** | F1 没有 IO 输出指令 |
| 驻留 | **（丢弃）** | F1 没有 G4 |
| 等运动停止 | **（丢弃）** | 一问一答天然同步 |
| 模态设置 | **（丢弃）** | F1 默认绝对坐标 mm |

**验证**：编译一个 8mm 方块 + 格栅的工程，输出 277 行，**零非法指令**。

### 10.2 串口连接模块

`app/serial_f1.py`：

- `build_frame()` 构造 `@正文*CRC\r`，支持 `FFFF` 旁路
- `parse_response()` 解析 `E<2位>*CRC\r` 和 `D L.. R.. P..*CRC\r`
- `LCSerialLink` 封装 pyserial，提供 `open/close/ask/query_status/snapshot`
- `SerialJob` 逐行下发，自动跳过注释、超长行报错
- `list_serial_ports()` 列出串口并标记「可能是板子」（CH340/CP210/FTDI）

**单元测试**：33 项全过，CRC 值与协议文档逐字符吻合。

### 10.3 前端改造

- 「输出目标」下拉新增 `LCSystemF1（串口板）` 并设为默认
- 「连接机器」面板新增「连接方式」切换（串口 / 网络）
- 串口模式：下拉选 COM 口（自动选中标记为板子的那个）+ 波特率
- 手动指令占位符从 `M121 U0 V1` 改为 `M50`

### 10.4 端到端实测

从 UI 画方块 → 套用格栅预设 → 填充 → 生成 G-code → 连接 COM7 → 发送：

```
[1] 画方块: 1 个
[2] 预设: 间距=2
[3] 填充: 10 个形状
[4] 编译: 60 笔画 · 729.6mm
[5] G-code 277 行, 非法指令: 无
```

**坐标随 G-code 正确变化**，证明运动链路完整可用。

### 10.5 已知限制

| 限制 | 影响 | 解决方向 |
|---|---|---|
| F1 无 IO 输出 | **无法控制气阀**，只能空跑轨迹 | 加继电器/MOS 模块，或换带 IO 的主板 |
| F1 无 G4 驻留 | 无法在板内做延时 | 驻留靠上位机 sleep，但一问一答会拖慢 |
| F1 无 G92 | 坐标只能靠 G28 或断电清零 | 让固件加 G92 |
| 运动中阻塞 | 无法实时读位置 | 进度按笔画估算 |
| 固件比文档旧 | `G28 X` 不支持 | 让朋友更新固件 |
