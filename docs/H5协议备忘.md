# H5 板通信协议备忘

> 面向技术人员。以**实机验证结果**为准，与官方文档 `LCSystemH5通信协议_v1.1.pdf` 有出入的地方已标红说明。
>
> 适用：H5 以太网板（当前主力板）
> 最后验证：2026-11-21，4 个步进电机 + IO 实测

## 1. 连接

| 项 | 值 |
|---|---|
| 传输层 | UDP / IPv4，无连接、无重传、无流控 |
| 板端 IP | `192.168.0.102/24` |
| 板端网关 | `192.168.0.100` |
| 监听端口 | `5000` |
| 电脑网卡 | 静态配 `192.168.0.100/24` |

**多网卡机器注意**：发送前必须把 socket 绑到板子所在的网卡，否则流量可能从 WiFi 出去收不到回包。

```python
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("192.168.0.100", 0))     # ← 关键
s.sendto(b"M114\r", ("192.168.0.102", 5000))
```

**排查顺序**（不通时按此顺序，别先怀疑协议）：

```powershell
Get-NetAdapter | Select-Object Name,Status,LinkSpeed
#   LinkSpeed 0 bps = 物理层没通（网线或供电），此时发包无意义

Get-NetNeighbor -AddressFamily IPv4 | Where-Object {$_.IPAddress -like '192.168.0.*'}
#   MAC 全 0 且 Unreachable = 二层都没通
```

## 2. 报文格式

### 下行（上位机 → 板端）

纯文本，**行尾必须是 CR（`\r`，0x0D）**。

```
M114\r
G1 X50 F3000\r
```

支持的后缀：

| 语法 | 处理 |
|---|---|
| `;` 之后 | 整行注释丢弃 |
| `(...)` | 括号内丢弃 |
| `N10` | 行号，摘出后不参与执行 |
| `*nn` | 校验和 |

### 校验和（注意不是十六进制）

```
1. 取 * 之前的全部字符，逐字节 XOR，得到 0~255 的值
2. XOR 包含空格、Tab 和原始大小写
3. 排除 ; 之后、() 内部、CR/LF/NUL
4. 把这个值写成十进制数字串
```

| 原始文本 | XOR 值 | 合法写法 |
|---|---|---|
| `G1 X50 F3000` | 110 | `G1 X50 F3000*110\r` |
| `M120 I3` | 36 | `M120 I3*36\r` |

> ⚠️ **不要写 `*FFFF`**。旧 R7 协议用十六进制，H5 改成了十进制。
> 普通调试可以直接省略校验和。

### 上行（板端 → 上位机）

每包正文后追加 `\r`，包内多行同样用 `\r` 分隔。

`M120 I3` 的完整回包（22 字节）：

```
"B000\r" + "IOIN3=0 active=1\r"
```

### 结果码：E 码与 B 码

| 行类型 | 回复字母 | 示例 |
|---|---|---|
| 含 G 字的行（含 G+M 混合） | **`E`** | `G1 X50 F3000` → `E000` |
| 无 G、至少一个 M 字的纯 M 行 | **`B`** | `M114` → `B000` |
| 只有轴字 / 续行 / 解析失败 | `E` | 走标准错误码表 |

两种字母共用同一张状态码表，**只有首字母不同**。回码统一 4 字节 `%c%03u`。

> **判定成功的唯一依据是最终的 `E000` / `B000`**，不是 echo，也不是 `queued #N`。

## 3. 执行模型

```
上位机 ──UDP──► [UDP 任务] ──队列(深8)──► [运动任务] ──► 电机驱动 ×4
   ▲               │                        │
   │               │ 入队即回 queued #N     │ 跑完写结果队列
   └── E/B 结果包 ─┴────────────────────────┘
```

**异步队列模式（默认）**：收包即入队返回；运动任务串行执行，完成后把结果放入结果队列，UDP 任务每 50 ms 轮询一次并发回。

**快查询通道**：纯 `M120` / `M121` **不进队列**，在 UDP 任务里立即执行，回码直接写进入队回执包。

> 这条很关键：**当运动队列被长任务占满时，`M120`/`M121` 仍然可用**，可以继续读状态、关 IO。

**队列深度**：8 条。超发回 `E020`，该行被丢弃。

## 4. 状态码

`001`~`015` 与固件 `GcodeStatus` 枚举一一对应。

| 码 | 含义 | 上位机处理 |
|---|---|---|
| `000` | 完全正确 | 继续下一条 |
| `001` | 空行 / 纯注释 | 当前实现不回包 |
| `002` | 非法字母 | 修正后重发 |
| `003` | 数值非法（字母后无合法数字） | `G28 Z` 可省值，`G0/G1`、`G92` 必须写值 |
| `004` | 同一字母在一行重复（G/M/N 除外） | 修正 |
| `005` | 模态冲突（如 `G90 G91` 同行） | 拆成两行 |
| `006` | `*nn` 校验和不符 | 重发或去掉校验和 |
| `007` | — | — |
| `009` | 不支持的指令 | 不要发 |
| `010` | 参数超范围 | 检查数值 |
| `012` | `M400` 等待超时（10 分钟） | 检查是否卡住 |
| `015` | 回零时开关顺序不对 | 查线，确认原点/限位接对 |
| **`020`** | **运动队列满（8 条），本行丢弃** | 降低并发，稍后重发 |
| `021` | 入队失败（参数异常） | 重发 |
| `022` | 单行超过 128 B | 拆行 |
| `999` | 未知错误兜底 | 看串口日志 |

## 5. 指令集

### G 指令

| 指令 | 参数 | 功能 | 备注 |
|---|---|---|---|
| `G0` | `X Y Z E`（任选）、`F` | 快速定位 | 不带 `F` 用 `M203` 设的速度（默认 6000） |
| `G1` | `X Y Z E`（任选）、`F` | 直线插补 | 四轴按位移比例同步加减速；不带 `F` 用模态 F（默认 1500） |
| **`G4`** | **`P` 或 `S`** | **延时** | **单位是秒！见下方警告** |
| `G20` / `G21` | — | inch / mm（默认 mm） | 影响后续坐标与 F |
| `G28` | `X Y Z E`（可选，可只写字母） | 回参考点 | 不写则四轴全回 |
| `G90` / `G91` | — | 绝对（默认）/ 相对 | G90 重复发同一坐标 = no-op，回 000 但不动 |
| `G92` | `X Y Z E`（可选） | 设当前点为指定显示值 | 只改显示零点，不产生运动，绕不过软限位 |
| `G94` | — | 每分钟进给 | 已支持，无实际差异 |

**不支持**：`G2/G3` 圆弧、`G29`、`M104/M109` 温度、`M119` → 均回 `009`。

### 🔴 `G4` 的时间单位是秒，不是毫秒

官方文档写 `P（ms）`，**实测是秒**。这是最容易踩的坑。

实测数据（已扣除约 76 ms 通信基准）：

| 指令 | 实测延时 | 说明 |
|---|---|---|
| `G4 P1` | 1018 ms | **P1 = 1 秒** |
| `G4 P10` | 9998 ms | **P10 = 10 秒**，严格线性 |
| `G4 S0.1` | 86 ms | S 也是秒 |
| `G4 P0.12` | 137 ms | 小数可用，对应 120 ms |
| `G4 P0.08` | 86 ms | 对应 80 ms |
| `G4 P0` | 瞬时 | 零延时正常 |

**正确用法**：开阀延时 120 ms 写 `G4 P0.12`，关阀延时 80 ms 写 `G4 P0.08`。

> 按文档发 `G4 P100` 以为是 100 毫秒，实际板子会睡 **100 秒**。期间所有指令无回包，极易误判为"板子卡死"。
>
> **测试任何带时间参数的指令，一律先用最小值试探，用实测耗时反推单位。**

### M 指令

| 指令 | 参数 | 功能 | 备注 |
|---|---|---|---|
| `M92` | `X/Y/Z/E<mm/圈>` 或 `S<mm/圈>` | 设/查丝杆导程 | 默认 60；不写参数=查询；合法 0.01~1000；掉电不保存 |
| `M203` | `V<mm/min>` | 设 G0 快速速度 | **不支持无参查询**（会回 `B003`） |
| `M204` | `A<mm/s²>` `D<mm/s²>` | 设加/减速度 | 可只写一个 |
| `M400` | — | 等待运动停止 | 超时 10 min 回 `012` |
| `M114` | — | 报工作坐标 | `X:.. Y:.. Z:.. E:..` |
| `M120` | `I<n>` `O<n>` `U<n>`（可选） | 读 IOIN / IOORG / IOOUT | 不写字母=三组各读；单路读额外回 `active=0/1`；走快通道 |
| `M121` | `U<n> V<0\|1>` 或 `T1`；或 `V<掩码>` | 写 IOOUT | `U3 V1` 置高、`U3 T1` 翻转、`V255` 掩码写多路；越界回 `010`；走快通道 |
| `M154` | `P<n>`（可选） | 读详细位置 | 不写 P=四轴全报+state；`P0~P3` = X/Y/Z/E；**走 SPI，必须排队** |
| `M17` | — | 使能驱动 | ENN 由硬件 10K 下拉固定使能，实为空操作 |
| `M18` / `M84` | — | 禁用功率级 | **当前硬件无效**，不能用软件断电 |

## 6. IO 语义

### 🔴 输出实际只有 4 路

官方文档写 8 路，**实测只有 `U0`~`U3`**。

| 测试 | 结果 |
|---|---|
| `U0`~`U3` 逐路置高 | ✅ 全部读回 `=1` |
| `U4`~`U7` 逐路置高 | ❌ 读回 `255`（无效） |
| `M121 V255` | 只有 `IOOUT 0x0F`（低 4 位） |

**掉电默认状态**：`IOOUT 0x00`（全关），断电不会漏料。

### 输入与原点

| 组 | 通道 | 语义 |
|---|---|---|
| `IOIN` | 0~7 | 行程限位，**低有效**。`0xFF` = 无限位触发 |
| `IOORG` | 0~3 | 原点开关，**高有效**，对应 X / Y / Z / E 四轴 |
| `IOORG` | 4~7 | 未使用 |

四轴同时压在原点时位图为 `0x0F`（bit0~bit3）。

## 7. 读回包格式

```
M120         →  IOIN 0xFF 11111111
                IOORG 0x00 00000000
                IOOUT 0x00 00000000
                ok

M120 I3      →  IOIN3=0 active=1
M120 U0      →  IOOUT0=1
M121 U0 V1   →  IOOUT0=1
M114         →  X:0.000 Y:0.000 Z:0.000 E:0.000
M92          →  （导程值）
M154         →  X work=0.000 mach=0.000 step=0 spu=853.333 lead=60.000
                （四轴各一行）
```

**`M154` 的字段含义**：

| 字段 | 含义 |
|---|---|
| `work` | 工作坐标（受 G92 影响） |
| `mach` | 机械坐标 |
| `step` | 步进计数 |
| `spu` | steps per unit，步/mm |
| `lead` | 丝杆导程，mm/圈 |

实测本机：`spu = 853.333`、`lead = 60.000`，即每圈 51200 步（256 细分）。

## 8. 上位机实现要点

### 一问一答 + FIFO 配对

结果包**不带票号**，靠「板子严格串行执行、结果顺序 == 发送顺序」做 FIFO 配对。

批量发送时：一包发 N 条，按顺序等 N 个结果码。带延时的行要独占一窗。

### 每包可能有三段

```
① queued #1 (0 pending)     ← 入队回执
② G1 X50 F3000              ← 原文 echo
③ E000                      ← 真正的结果
```

**解析时不能一见 `E000` 就返回**，要先把整包扫完，否则会丢掉后面的 IO 数据。

### 每条指令前先 drain

板子的 echo 可能比结果码晚到，残留在 socket 缓冲里会被下一条指令误读成自己的响应。发送前清空缓冲：

```python
s.settimeout(0.15)
try:
    while True:
        s.recvfrom(4096)
except socket.timeout:
    pass
```

### 长任务期间不要发队列指令

`G4 P10` 期间发 `M114` 会一直无回包——**不是在卡死，是板子在忙**。只有 `M120`/`M121`（快通道）能穿透。

## 9. 与前代板（R7）的差异

| 项 | R7 网口板 | H5 |
|---|---|---|
| 回码字母 | 全 `E` | G 行 `E`、M 行 `B` |
| 校验和 | 十六进制，`FFFF` 可跳过 | **十进制 XOR** |
| `G4` | **不可用**，发了卡死队列 | ✅ 可用，单位是秒 |
| 轴数 | 3 轴 | **4 轴 XYZE** |
| `G92` | 无 | ✅ 有 |
| IO 输出 | 8 路 | **4 路** |
| 快查询通道 | 无 | ✅ 有 |

**同一个方言实现要能区分这两块板**，用能力字段（`dwell`、`io_channels`）声明差异，不要写死。
