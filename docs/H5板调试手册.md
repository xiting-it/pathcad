# H5 板调试手册

> 面向接线与调试。**以实机验证结果为准**，与官方文档不一致的地方已明确标出。
>
> 适用：FSCSystem01 运动控制器（协议文档称 LCSystem H5）
> 最后更新：2026-11-21，四轴 + 4 路 IO 实机验证

---

## 1. 这块板是什么

| 项 | 值 |
|---|---|
| 型号 | FSCSystem01 运动控制器 |
| 轴数 | 四轴步进（X / Y / Z / U） |
| 驱动 | **板载集成**，可驱 42 / 57 / 86 三种规格电机 |
| 电源输入 | **12~48V，5A** |
| 步进分辨率 | 1/256 微步，944,000 微步/秒 |
| 尺寸 | 172 × 140 × 20 mm |
| 上位机通信 | 10M/100M 以太网（非 ethercat） |
| 数字输入 | 16 路光电隔离（可配为原点 / 限位） |
| 数字输出 | **4 路光电隔离** |
| 扩展 | 1 个 CAN FD（可选） |

**分辨率换算**：`853.33 微步/mm` = 51200 微步/圈 ÷ 60mm 导程。

## 2. 两套电源，必须分清

这是最容易出问题的地方。

```
USB / 5V         →  逻辑电路、网络、IO      逻辑活了不代表功率级活了
12~48V, 5A       →  步进驱动器的功率级（VMOT）
```

### ⚠️ 关键陷阱：电源指示灯亮 ≠ 电机有电

**电源灯亮只说明空载电压存在，不代表带载能力正常。**

真实案例：一个步进电机内部短路后，把 12~48V 拉垮。
表现为：**通信完全正常、回码正常、坐标照变，但四个电机全都不转、也都不热。**

判断方法：
- 电机**拧得动**（只有齿槽力）+ **不烫** → **线圈里没有电流**
- 电机**拧不动 / 很硬** + 运行一会儿变温 → 线圈有电流

## 3. 电机接口

左侧一列，**从上到下依次是 CN9、CN8、CN7、CN6**（编号由下往上递增，容易看串）。

| 丝印 | 轴 | 说明 |
|---|---|---|
| CN9 | **U** | 第四轴 |
| CN8 | **Z** | 抬针 / 落针 |
| CN7 | **Y** | |
| CN6 | **X** | |

每个接口 4 针，接步进电机四线。

### 第四轴字母：协议用 `E`，丝印写 `U`

协议层发指令必须用 **`E`**：
```
G1 E10 F300     → E000（成功）
```
丝印上的 `U` 是板子标注，不要用在指令里。

### ⚠️ 步进电机四线不能接错

四根线是两组独立线圈：`A+/A−` 和 `B+/B−`。

**接错一个针位的后果**：
- 磁场不旋转 → **电机完全不转**
- 电能全部变成热量 → **几分钟就烫手，发出漆包线糊味**
- 严重时烧穿绕组绝缘

**判断接线是否正确的最快方法**：发一条让电机连续转 2 秒的指令，看它转不转。

## 4. 首次上电流程

**严格按顺序做，不要跳步。**

### 第 0 步：断电状态下的检查

- [ ] 电机电源（12~48V）接线正确、电压正常
- [ ] 板上有无保险丝（丝印 `F1`/`F2`），量一下通断
- [ ] 四个电机插头都插紧
- [ ] 急停按钮（如果有）处于释放状态
- [ ] **电机轴上没有机械负载**（第一次测试必须空载）

### 第 1 步：只上逻辑电源，确认通信

```bash
# 电脑网卡配静态 IP
# 地址 192.168.0.100   掩码 255.255.255.0
ping 192.168.0.102
```

不通时**先查网卡状态**，不要怀疑协议：

```powershell
Get-NetAdapter | Select-Object Name,Status,LinkSpeed
# LinkSpeed 0 bps = 物理层没通（网线/供电），此时发包毫无意义
```

### 第 2 步：上电机电源，听声音

上电后四个电机应该**有保持力矩**（拧不动或有明显阻力）。

用手拧一下：
- 硬、涩 → 有电流 ✓
- 和断电一样轻松 → 没电流，查电源或接线

### 第 3 步：逐轴点动

**一次只动一个轴**，动完停 2 秒观察。

```bash
python dev/_h5_spin_all.py --seconds 2 --feed 300 --pause 2
```

每轴连续转 2 秒（走 10mm），记录：

| 轴 | 接口 | 会转吗 | 顺时针/逆时针 | 手感温度 | 备注 |
|---|---|---|---|---|---|
| X | CN6 | | | | |
| Y | CN7 | | | | |
| Z | CN8 | | | | |
| U | CN9 | | | | |

**空载状态下只能判断转向，判断不了「往右是正方向」**——真正的方向标定要等装上机械结构。

### 第 4 步：方向不对怎么办

**不要拆线重接。** 软件里有开关：

```
机器 → 机器设置… → 轴方向反转 → 勾选对应轴
```

勾上之后该轴坐标取负，不用动机器。

### 第 5 步：才允许跑任务

跑任务前先确认：
- [ ] 四个轴都会转，方向正确
- [ ] 行程范围设置合理（**尤其 Z 行程，见下方陷阱**）
- [ ] 工具通道号与板子实际的 IO 路数匹配（只有 4 路）

## 5. 四个必须知道的陷阱

### 陷阱 1：安全高度被设成机器行程

**曾经的真实事故**：`Z 行程` 默认填 100，编译器把「安全高度」算成 `max(行程, 抬针+1) = 100`，
于是任务第一条指令是：

```
G0 Z100 F3000
```

如果机器的 Z 实际只能动几毫米，这一条就是**顶着限位堵转**——
电机满电流不转，一直堵着，几分钟后烧毁。

**已修复**：安全高度现在按「最高层 + 抬针 + 1mm」计算，再受行程约束。
正常值应该是 1~5mm 量级，**看到 `GZ Z100` 这种就该警觉**。

### 陷阱 2：`G4` 的时间单位是秒，不是毫秒

官方文档写 `P（ms）`，**实测是秒**：

| 指令 | 实测 |
|---|---|
| `G4 P1` | 1018 ms（= 1 秒） |
| `G4 P10` | 9998 ms（= 10 秒） |
| `G4 P0.12` | 137 ms（= 120ms，小数可用） |
| `G4 P0` | 瞬时 |

所以 120ms 的开阀延时写 `G4 P0.12`，不是 `G4 P120`。

按文档写 `G4 P100` 以为 100 毫秒，实际板子会睡 **100 秒**，期间所有指令无回包——
很容易误判成"板子卡死了"。

**通用规则**：任何带时间参数的指令，首次测试一律先用最小值，用实测耗时反推单位。

### 陷阱 3：IO 输出只有 4 路

协议文档 §6.1 和板子规格都写 **`IOOUT 0~3`**，实测一致：

- `U0`–`U3` 可用
- `U4`–`U7` 读回 `255`（无效）
- `M121 V255` 实际只有 `IOOUT 0x0F`

阀门超过 4 个就需要外部 IO 扩展。

### 陷阱 4：中止 ≠ 立刻停机器

板子的三条硬限制（制作组确认）：

| 限制 | 后果 |
|---|---|
| 不支持断点续传 | 中止后只能从头重打 |
| **不支持队列清空** | 队列里的命令必须执行完 |
| 只能断电清空 | 想立刻停，只能拔电 |

**中止时板子队列里最多还有 8 条命令 + 在途一包**，按单条 0.5 秒算要 3~7 秒才真的停。
这段时间点「重新发送」，新命令会排在旧命令后面，机器动作完全错乱。

软件已做的处理：中止后自动发 `M400` 等队列排空，期间禁止重发。

### 陷阱 5：软限位实测值与文档不一致

协议文档写「X ±1000、Y ±1000、Z ±500、E ±5000」。**实测 Y 是 ±2000**：

| 轴 | 文档 | 实测 |
|---|---|---|
| X | ±1000 | ±999.5 ✓ |
| **Y** | ±1000 | **±2000** |
| Z | ±500 | ±500 ✓ |

越界回 `E010`，该行**不会产生运动**（下发前预检，安全，可用于探测限位）。

另外文档说「进给为负」也会回 `E010`，**实测不会**：

```
G1 X1 F-600  → E000
G1 X1 F0     → E000
```

### 陷阱 6：偶发 E010（不可复现）

有一个至今没查清的现象，记录备查：

```
任务跑到第 152/243 行，某条 G1 X-0.956 Y2.997 F600 回 E010
但：单独发这条        → E000
    整包 6 条重发 5 次 → 全部 E000
    坐标远在软限位之内
```

特征：**回码只比前一条晚 12ms**（正常一条运动要 220ms），说明是被预检立即驳回的，根本没有执行。

判断是固件的判定边缘情况，1/243 的概率，无法稳定复现。
软件侧已做处理：`E010` / `E020` 会自动单独重发一次，重发几乎必然成功。

如果频繁出现，把日志里的原始报文（含 hex）交给板子组排查。

## 6. 故障对照表

| 现象 | 最可能的原因 | 怎么查 |
|---|---|---|
| 网卡 `0 bps` | 网线没插好 / 板子没上电 | 换线、查电源 |
| ping 不通但网卡 Up | IP 网段不对 / 防火墙 | 查 IP、临时关防火墙 |
| 通信正常但**四个电机全不动** | **电机电源（VMOT）没电** | 量 12~48V 输入；查保险丝 |
| 单个电机不转且很快发烫 | **接线错 / 线圈断** | 万用表量绕组：应有两组阻值接近的配对 |
| 单个电机不转但不烫 | 该路驱动故障 | 把好电机插到该口试 |
| 电机转但板子不报成功 | 协议/回码问题 | 看回码是 `E000` 还是错误码 |
| 回码正常、坐标在变、但不转 | 开环系统无反馈，或降级通道 | 手拧测保持力 |
| 发 `G4` 后板子无响应很久 | `P` 单位是秒，睡太久了 | 等它跑完，或断电 |
| 回 `E020` | 运动队列满（8 条） | 降低并发 |
| 回 `009` | 不支持的指令 | 查指令集 |
| 回 `014` | 限位被压住 | 查限位开关与接线 |
| 中止后重发动作错乱 | 队列没排空 | 等「队列已清空」提示 |

## 7. 禁止事项

1. **严禁带电插拔电机线。** 步进电机是感性负载，带电断开产生反电动势，**直接击穿驱动芯片**。所有接线操作必须断电。
2. **严禁让电机长时间堵转。** 满电流不转，几分钟就能烧毁绕组。
3. **烧过 / 闻到过糊味的电机不要再用。** 内部可能已短路，会连带烧驱动。
4. **不要按文档写 `G4 P100`。** 单位是秒。
5. **不要以为电源灯亮就等于电机有电。**
6. **不要在电机空载时跑长任务。** 空载无法暴露机械问题，只会白耗时间。

## 8. 恢复手段

| 情况 | 手段 |
|---|---|
| 队列卡死 | **断电重启**（唯一手段） |
| 长 `G4` 期间 | 等它跑完，不要发包 |
| 坐标错乱 | `G92` 重设零点，或断电 |
| IO 状态不明 | `M121 V0` 全关 |

**板子不会自己恢复。** 出现任何异常，第一选择是断电重启。

## 9. 通信配置备忘

```python
# UDP 必须绑定到板子所在的网卡，否则可能从 WiFi 出去收不到回包
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("192.168.0.100", 0))
s.sendto(b"M114\r", ("192.168.0.102", 5000))
```

- 板端 `192.168.0.102:5000`，无 DHCP，静态配置
- 行尾必须是 **CR（`\r`，0x0D）**
- 校验和是**十进制 XOR**（如 `*110`），不是十六进制，普通调试可省略

**回码规则**：
- 含 G 字的行 → **`E` 码**
- 纯 M 行 → **`B` 码**
- 判定成功的唯一依据是最终 `E000` / `B000`，不是 echo、不是 `queued #N`

**三个独立的包**：`queued #N` → 原文 echo → 结果码。中间隔几十毫秒，解析时要收满。
