# 3D 路径规划上位机 · 文档索引

> 目标：做一个上位机软件，让用户自由画路径（线段/矩形/填充/图像），每条路径的起点和终点各控制一个 IO + 一个延时，输出 G-code。
>
> 硬件背景：朋友提供自研开发板（LCSystem，i.MX RT1170 + TMC5160，UDP G-code），未来可能走 Ultimaker/Marlin 或 Klipper。

## 为什么是「1 份内核 + 2 份方案」

不是两套软件。你的需求模型（笔画 + 两端事件 + 延时）在三种硬件上是同一件事：

| 层 | 三种硬件 | 结论 |
|---|---|---|
| 编辑器 | 完全一样 | 共用 |
| 几何/填充/排序 | 完全一样 | 共用 |
| 笔画数据模型 | 完全一样 | 共用 |
| 标定表 | 结构一样，数值不同 | 共用结构 |
| 后处理器骨架 | 一样 | **方言实现不同** |
| 下发器 | UDP / 串口 / HTTP | 各写各的 |

**如果写两套独立设计，几何、填充、标定、mock 板都要复制一遍，改一个 bug 要改两处。**

关键抽象是 `Dialect` 接口里的一个字段：

```ts
caps: { queuedIO: boolean }
```

- `true`（Klipper）→ 直接输出「阀开 → G4 → G1」，时序精确
- `false`（Marlin / 自研板待测）→ 自动在每个 IO 指令前插 `M400`，强制停车换正确性

**一个字段，把「两套方案」压缩成了配置。**

## 三条路的对比

| | 自研 LCSystem | Ultimaker/Marlin | Klipper |
|---|---|---|---|
| 阀指令 | `M121 U<n> V0/1` | `M42 P<pin> S0/1` | `SET_PIN PIN=valve VALUE=1` |
| IO 随运动排队 | ⏳ 待测 | ❌ 确定不排队 | ✅ 架构保证 |
| 需要 `M400` | 待测 | ✅ 必须 | ❌ 不需要 |
| 移动中开阀 | ⏳ | ❌ | ✅ |
| 改配置要重刷 | 改宏+刷机 | 重编固件 | 改 cfg + 重启 |
| 队列深度 | 8 | 16 | 无硬限 |
| 行长度 | 128 B | 96 B | 无硬限 |
| 通讯 | UDP 无重传 | 串口 `ok` 握手 | Moonraker HTTP |
| 无前瞻 | 可能 | ✅ 有 | ✅ 优秀 |
| 圆弧 | ❌ | ✅（不用） | ✅（不用） |
| 控制面板 | 自己写 | 自己写 | **Mainsail/Fluidd 白嫖** |

**技术上 Klipper 最正确。** 自研板如果照 Klipper 的 `output_pin.py` 改固件（几十行），就能达到同样水平。

## 核心结论速查

### 这个需求没有现成方案

开源膏体/DIW 圈全部靠「假装成 E 轴」或「拿风扇口凑」，**没人把「每笔画独立的 pre/post 延时」做成参数**。这是真缺口，也是你的差异化。

### 最接近的先例是笔式绘图仪

vpype-gcode 的 `line_start` / `line_end` 就是「每条路径的起点/终点模板」，官方示例里已经包含 `M3 S1000 → G4 P0.3` 这个模式。**直接抄这套 schema。**

### 三个必须知道的坑

1. **Marlin 的 `M42` 不排队** —— [issue #26803](https://github.com/MarlinFirmware/Marlin/issues/26803)，50–100ms 驻留不可靠，要 1000ms。必须插 `M400`。
2. **驻留要在关阀之后** —— 停车瞬间会多挤一点（T-Code 论文实测），先停再关会鼓包。
3. **无前瞻时单段至少 1.5mm** —— 加速距离 `F²/(2a)`，F=600mm/min、a=300mm/s² 时是 0.17mm，但为了速度稳定要多留余量。

### 一个硬件建议

**加一路排气阀**（或改用 3/2 阀）。防拉丝的根本机制不是等余压衰减，是**强制泄压**。Frostruder、Claystruder 都是这么做的，Duet 论坛上的商业膏体打印机也是。

**→ IO 需求从「1 路」改成「至少 2 路」。**

### 一个协议改进建议（给朋友）

自研板缺两个东西，RepRapFirmware 有而它没有：

- **`M571 P<n> S1`** —— "output on extrude"，正挤出时为高。不用手动开关，声明一次就行
- **`M670 T<ms> P<port>`** —— 端口切换提前量，阀在运动开始**之前**打开

以及最关键的：**`M121` 要随运动排队，不要解析器执行**。照 Klipper 的 `register_lookahead_callback` 做，成本几十行。

## 待确认清单

### 问朋友（硬件方）

1. **第 4 轴（固件里的 E / 现场标的 U）驱动什么？**
   如果是注射器推杆 → 可按体积控制，整套逻辑不一样（跳过气压滞后问题）。如果是空的 → 纯开关阀模型。

2. **IOOUT 8 路怎么分配？**
   现在需要**至少 2 路**：主挤出阀 + 排气/回抽阀。还有别的执行器吗（UV 灯、第二组份阀、报警）？

3. **阀的电气特性**
   - 有没有 MOS/继电器板？（`M121` 只有 3.3V 逻辑，**直接驱动会烧 IO**）
   - 高电平开还是低电平开？
   - 常闭还是常开？断电时什么状态？（安全关键）

4. **`M121` 是解析器执行还是队列同步？**
   有没有类似 `M571`/`M670` 的机制？

5. **真机行程和原点开关**
   协议默认软限位 X/Y ±1000、Z ±500，显然不是真机值。三个轴的原点开关都装了吗？

6. **气压能不能软件调？**
   手动调压阀 → 一条笔画内流量恒定；有 IO/串口接口 → 可做变线宽。

### 自己定

- 最终目标机是只跑自研板，还是也要支持 Klipper？（决定后处理器要不要做方言可插拔）
- 延时单位统一 ms？（建议是）
- 一条笔画首尾是否允许不同 IO 通道？（schema 已留，默认同通道）
