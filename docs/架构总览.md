# 架构总览

> 面向技术人员。**本文件描述的是 beta1.4 阶段的架构**，P3 里程碑（数据模型 + IR 重构）会改动第 2、3 层，届时本文件需同步更新。

---

## 1. 这是什么

**CAM-B 是一个「路径工艺平台」**：用户画出路径，路径绑定工具与工艺参数，编译成控制器能执行的指令，下发到硬件。

它不是切片器。切片器是「模型 → 逐层轮廓 → 填充」，而这里的核心是**路径本身就带工艺事件**——每条路径的两端各自控制一个输出并附带延时。

```
             切片器                     CAM-B
输入     STL/OBJ 三维模型          手绘 / SVG / 三维模型
核心     层轮廓 + 填充             路径 + 两端事件 + 工艺参数
输出     G-code（固定格式）        指令序列（格式由方言决定）
```

支持与计划支持的工艺：

| 工艺 | 状态 | 路径两端的事件 |
|---|---|---|
| 气动挤出（DIW） | ✅ 已实现 | 开关阀 + 开/关延时 |
| 激光切割 | 🔶 接口预留 | 激光开关 + 功率 |
| 激光打标 | 🔶 接口预留 | 激光开关 + 功率 + 频率 |

## 2. 分层

```
┌─────────────────────────────────────────────────────┐
│  ① 编辑器（web/）                                    │
│     画布、图元、吸附、标尺、属性面板                   │
│     产出：带两端事件的笔画列表                        │
└───────────────────────┬─────────────────────────────┘
                        │  纯数据（JSON）
┌───────────────────────▼─────────────────────────────┐
│  ② 路径编译器（app/compiler.py + geometry + infill）  │
│     离散化、填充、排序、切段                          │
│     产出：按执行顺序排好的笔画                        │
└───────────────────────┬─────────────────────────────┘
                        │  纯数据
┌───────────────────────▼─────────────────────────────┐
│  ③ 后处理器 / 方言（app/dialects.py）                 │
│     把笔画翻译成目标控制器的指令                      │
│     产出：指令文本 + 每行后的延时                     │
└───────────────────────┬─────────────────────────────┘
                        │  纯数据
┌───────────────────────▼─────────────────────────────┐
│  ④ 下发器（app/link.py / serial_f1.py）              │
│     按协议打包、发送、配对回包、执行延时              │
│     产出：真机动作                                    │
└─────────────────────────────────────────────────────┘
```

**层与层之间只传纯数据**，每层可以独立测试。这是整个设计最重要的性质——换硬件不用碰几何，改几何不用碰协议。

> ✅ P3 已完成：② 现在产出 IR（`app/ir.py`），③ 通过 `render_instr()` 渲染。
> 第 ①④ 层不受影响。这是接入激光等非 G-code 控制器的基础。

## 4. 核心抽象：能力字段驱动方言

这是「一套编译器适配多种硬件」的关键。

```python
class DialectCaps:
    queued_io: bool        # IO 是否随运动排队
    dwell: str             # "gcode" | "host" | "none"
    max_line_len: int      # 单行长度上限
    io_channels: int       # IO 路数
```

| 字段 | 影响什么 |
|---|---|
| `queued_io` | True → 不插 `M400`（IO 会自然排在运动后）；False → 每个 IO 前插 `M400` |
| `dwell` | `gcode` → 延时写进指令；`host` → 上位机 sleep；`none` → 丢弃 |
| `io_channels` | 校验通道号是否越界 |

**现有方言**：

| 方言 | 板子 | queued_io | dwell | io_channels |
|---|---|---|---|---|
| `h5` | H5 网口板（**默认**） | True | gcode（`G4 P<秒>`） | **4** |
| `lc` | R7 网口板（旧） | True | host（上位机 sleep） | 8 |
| `f1` | F1 串口板 | True | none | 0 |
| `marlin` | 通用 3D 打印机 | False | gcode | 8 |
| `klipper` | Klipper 固件 | True | gcode | 8 |

> **H5 的 `G4` 时间单位是秒，不是毫秒**——120ms 要写 `G4 P0.12`。详见 `H5协议备忘.md`。

## 5. 两条不可违反的约束

这两条是物理决定的，不是偏好。违反会直接打坏件或打坏机器。

### 5.1 每条筋必须是独立笔画

```
❌ 错：蛇形连接
   ─────────┐
            │
   ┌────────┘
   └────────┐
            │
            └────────
   连接段带着工具开着走 → 在空白处漏料

✅ 对：每条独立
   ─────────
   ─────────
   ─────────
   每段各自开关工具
```

### 5.2 抬针 / 空驶 / 落针必须三段独立

```
❌ 错：合并成一条三轴联动
   G0 X0.4 Y0.6 Z0     ← 针头贴着工件表面斜着蹭过去，撞坏已打印部分

✅ 对：三段
   G0 Z0.3             ← 抬针（断料 + 留安全间隙）
   G0 X0.4 Y0.6        ← 空驶
   G0 Z0               ← 落针
```

**教训来源**：曾为了省指令数做过合并优化，指令数从 63 降到 46，但输出里出现 `G0 X0.4 Y0.6 Z0`，立刻发现危险并回退。

### 5.3 恒速打印（流体工艺）

开关式挤出的挤出量由阀的开关决定，不由速度决定。**速度一变线宽就变**，同一个件会粗细不均。

所以速度是**全局工艺约束**，不能做成按路径可调。

## 6. 数据流

```
用户画一笔
    │
    ▼
Stroke {
    points: [(x,y), ...],
    tool: "t1",              // 指向 Project.tools
}
Tool {
    on_channel, on_level, rise_ms,
    off_channel, off_level, tail_ms
}
    │
    ├─── 填充 ──► 一堆独立的填充笔画
    │
    ▼
compile_project(project, dialect)
    │
    ├── 排序、切段、生成抬针/空驶/落针
    ├── 按 DialectCaps 决定插不插 M400
    ├── 按 dwell 决定延时写指令还是留给上位机
    │
    ▼
Compiled {
    text: str,             # 完整指令文本
    lines: [str],          # 单行列表
    delays: [float],       # 每行之后等多少秒（host 模式用）
    stroke_count, path_length, warnings
}
    │
    ▼
JobRunner.send()
    │
    ├── 按协议打包（UDP 批量 / 串口一问一答）
    ├── FIFO 配对回包，校验结果码
    ├── host 模式：拿到结果码后 sleep
    │
    ▼
真机动作
```

## 8. 扩展点

面向团队与合作方开发者的扩展路径：

### 8.1 加一种新硬件

实现方言：

```python
# app/dialects.py
class MyBoardDialect(Dialect):
    caps = DialectCaps(
        queued_io=True,
        dwell="gcode",
        max_line_len=128,
        io_channels=4,
    )

    def emit_valve(self, io, level):
        return f"M121 U{io} V{level}"

    def emit_dwell(self, ms):
        return f"G4 P{ms/1000}"        # ← 注意单位
```

再在 `make_dialect()` 里注册。

> P3 之后这一步会改成实现「指令序列 → 你的格式」的转换器。

### 8.2 加一种新工艺

需要动三处（P3 之后会简化）：

1. 数据模型：给 `Stroke` 加工艺相关字段
2. 方言：加对应的 `emit_*` 方法
3. 界面：参数面板加工艺专属控件

> 这是 P3「工具/图层」重构要解决的——把工艺差异收进「图层参数」里，而不是散在三个地方。

### 8.3 加一种新图元

1. `model.py`：`Source.type` 加类型 + 字段
2. `geometry.py`：`_discretize_base()` 加分支
3. `web/app.js`：绘图工具 + `buildDraftPoints()`

## 9. 已知的架构债

诚实记录，供后续规划参考。

| 问题 | 影响 | 计划 |
|---|---|---|
| ~~输出是 G-code 文本~~ | — | ✅ P3 已解决：改为结构化 IR |
| ~~工艺参数硬编码在 `Stroke`~~ | — | ✅ P3 已解决：改为工具引用 |
| 速度仍可在单笔画上覆盖 | 与恒速打印约束矛盾，用户可能误改 | 计划升为全局或加约束提示 |
